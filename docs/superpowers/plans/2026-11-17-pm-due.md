# PM Due Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A read-only, meter-driven "PM due" list for machines on active Vantage contracts, with a PM
card on the device page and editable PM settings.

**Architecture:** Two new nightly worker jobs pull, GET-only from Vantage, (a) every machine's contract
links (active or not) and (b) 12 months of engineer visits (WorkUnits) plus open/future work. A pure
module in `@mps/db` turns visits + a combined (Black + Colour) meter series into a PM status per
machine; query functions feed a new `/pm` page, a CSV export, a device-page card and a settings page.
Nothing is written to Vantage.

**Tech Stack:** TypeScript, Drizzle + Postgres, pg-boss worker (tsx), Next.js app router, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-17-pm-due-design.md` (approved by user 2026-11-17).

## Global Constraints

- **Vantage is read-only**: GET only. Never POST/PATCH/PUT/DELETE, never `PMScheduleEntry/BulkImport`.
- Always send the `api-version` header (the client already does); OData date params in filters as ISO.
- 12-month window for visits (same `meterWindowStart` rule as `apps/worker/src/jobs/vantage-meters.ts`).
- Defaults (spec): PM interval **100,000** pages; time cap **12** months; qualifying visit **45** min;
  frequent calls **3** visits in **30** days; hold **30** days after last visit; due soon at **85%** or
  within **30** days. All editable; per-family interval override only.
- Active contract = existing rule `isActiveContract` in `packages/core/src/registration.ts` (StatusId 1,
  not on hold, no CancellationDate, not deleted), reached via `Meters → Charge → Contract` and
  `ContractCharges → Contract` (`contractsOf`). Export both; don't re-implement.
- Hidden devices (`notHiddenDevice`) never appear in the PM list.
- **No git commits during execution.** The branch carries ~45 earlier uncommitted paths that share files
  with this work (schema.ts, client.ts, queries/index.ts, admin-jobs.ts); the user OKs commits after a
  click-through and final review. "Checkpoint" steps below run the checks instead.
- Migrations: create tables + apply them **before** any web code queries them. Apply with
  `.\scripts\mps.ps1 stop -Only worker`, then `.\scripts\mps.ps1 start -Only worker` (the worker
  migrates on boot), or run `runMigrations` (`packages/db/src/migrate.ts`) alone.
- After web changes: `.\scripts\mps.ps1 build` (production build; restarts both).

## Review Focus

1. **Machine with Vantage readings but no DRMS link** — must still get a meter series (Vantage only) and
   a status; the PM list is keyed by Vantage equipment, not DRMS. Test in Task 4.
2. **Two WorkUnits same machine same day, 30 min each** — one visit, 60 min, qualifies; counts once for
   frequent calls. Test in Task 3.
3. **Meter goes down after the last visit** (board swap) — status Unknown with reason `meter_reset`,
   never OK/Overdue. Test in Task 3.
4. **No usable meters** — a qualifying visit 13 months ago still makes it Overdue by the time cap;
   no visit in the 12-month window at all = Overdue, reason `no_visit_12m`. Tests in Task 3.
5. **Visit dates in UK time** — a 23:30Z WorkStart on 31 Mar (BST) belongs to 1 Apr; group by
   Europe/London day. Test in Task 3.

### Task 3: Pure PM rules (`pm-due.ts`)

**Files:**
- Create: `packages/db/src/queries/pm-due.ts`, `packages/db/src/queries/pm-due.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export interface PmSettings { intervalPages: number; timeCapMonths: number; qualifyingMinutes: number;
    frequentCount: number; frequentWindowDays: number; holdDays: number; dueSoonPct: number;
    dueSoonDays: number; pmCategoryIds: number[] }
  export const DEFAULT_PM_SETTINGS: PmSettings // 100000, 12, 45, 3, 30, 30, 0.85, 30, []
  export interface VisitUnit { workUnitId: number; workId: number; reference: string | null;
    categoryId: number | null; categoryName: string | null; categoryType: string | null;
    start: Date | null; end: Date | null; logged: Date | null; hours: number | null; scheduled: Date | null;
    completed: Date | null }
  export interface Visit { day: string /* yyyy-mm-dd Europe/London */; at: Date; minutes: number | null;
    isField: boolean; isPm: boolean; units: VisitUnit[] }
  export type VisitVerdict = 'counted' | 'counted_pm' | 'too_short' | 'not_field' | 'unknown_length';
  export type PmStatus = 'booked' | 'held' | 'unknown' | 'overdue' | 'due_soon' | 'ok';
  export interface PmResult { status: PmStatus; reason: string | null; lastQualifying: Visit | null;
    pagesSince: number | null; pagesSinceIsLowerBound: boolean; pctUsed: number | null;
    pagesPerDay: number | null; estDueDate: Date | null; timeCapDate: Date | null;
    bookedFor: Date | null; frequentVisits: number; holdUntil: Date | null;
    visits: { visit: Visit; verdict: VisitVerdict }[] }
  export function unitMinutes(u: VisitUnit): number | null
  export function groupVisits(units: VisitUnit[], s: PmSettings): Visit[]          // past units only, newest first
  export function visitVerdict(v: Visit, s: PmSettings): VisitVerdict
  export function computePm(args: { units: VisitUnit[]; meter: YieldMeterPoint[]; intervalPages: number;
    s: PmSettings; now: Date }): PmResult
  ```
  `meter` = combined Black + Colour points (Task 4), sorted ascending. Reuse `meterPointAt` from toner-yield.

Rules to pin (spec values):
- `unitMinutes`: `hours*60` if hours > 0; else end − start if both set and < 24h; else null.
- `groupVisits`: units with `start ?? logged` in the past grouped by Europe/London calendar day; minutes
  summed (null only if every unit null); `isField` = any unit `categoryType === 'Field'`; `isPm` = any
  unit category in `s.pmCategoryIds`. Future/scheduled-only units are not visits.
- `visitVerdict`: not field → `not_field`; isPm → `counted_pm`; minutes null → `unknown_length`;
  < 45 → `too_short`; else `counted`.
- Booked: any unit with category in PM categories, `completed` null and `scheduled` ≥ today → `booked`, `bookedFor` = earliest.
- Held: ≥ 3 field visits inside some 30-day span whose last visit is within the last 30 days; `holdUntil` = last + 30d.
- Pages since: latest point − point at `lastQualifying.at`; null if either missing or latest.at ≤ visit;
  if latest < base → status `unknown`, reason `meter_reset`. No qualifying visit → latest − earliest in
  window, `pagesSinceIsLowerBound = true`.
- Rate: (last − point 90d earlier, or earliest if span ≥ 14d) / days; null otherwise. `estDueDate` from rate.
- Time cap date = lastQualifying.at + 12 months; no qualifying visit → overdue by time (reason `no_visit_12m`).
- Priority: booked > held > (overdue if pages ≥ interval or now ≥ timeCapDate) > unknown (no usable
  pages and time cap not reached; reason `no_meter`/`meter_reset`) > due_soon (pct ≥ 0.85 or est/time cap
  within 30d) > ok. (Time cap overrides unknown: spec "Unknown meter history does not block the time cap".)

  `PM-category visit of 10 min resets the clock (counted_pm)`; `40-min field visit is too_short and does not reset`;
  `booking visit is not_field`; `100k pages since counted visit → overdue`; `86k → due_soon`; `50k → ok`;
  `meter down after visit → unknown meter_reset`; `no meters, visit 13 months ago → overdue by time`;
  `no visits in window → overdue reason no_visit_12m with lower-bound pages`;
  `3 short field visits in 20 days, last 5 days ago → held, holdUntil = last+30d`;
  `future PM-category unit not completed → booked with date`; `est due date from 90-day rate within 30 days → due_soon`.
