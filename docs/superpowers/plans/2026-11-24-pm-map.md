# PM Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Map view on `/pm/planner` showing due PMs and engineers' booked calls as pins, where the office draws a box round machines and adds them to the plan or marks them "asked engineer" for a call without leaving the map.

**Architecture:** The DB layer gains `loadMapPins` (built from the same candidate list `loadUpcoming` already makes for suggestions, factored into `loadCandidates`) and `planFromMap` (batch add / batch ask with per-machine skip reasons). The planner page reads `?view=map` and passes pins + calls to a client-only Leaflet component (`next/dynamic`, `ssr: false`). Map actions are server actions that return a result (no redirect), then `router.refresh()`; the map keeps zoom, pan and day; selection clears.

**Tech Stack:** Next.js 16 app router, React 19, Drizzle/Postgres, vitest (real test DB for `packages/db`), Tailwind, `leaflet` + `react-leaflet` + `leaflet.markercluster`, sonner toasts (`@/components/ui/sonner`, already mounted).

**Spec:** `docs/superpowers/specs/2026-11-24-pm-map-design.md` (parent: `docs/superpowers/specs/2026-11-23-pm-planner-design.md`)

## Global Constraints

- Read-only toward Vantage; nothing sent to engineers. Writes go to `pm_plan` (+ audit) only, via existing `addToPlan` / `moveCard`.
- Customer names/addresses never sent to an outside service. Tiles only: `https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png` in one exported constant, attribution `© OpenStreetMap contributors`.
- Pins = PM due Due set incl. When-in-area, minus other dealer, dismissed, booked. Done not shown. Same exclusions as `suggestNear` (`view === 'due'`, `dealer === null`).
- Location: customer lat/lng, else postcode-district centroid (`approximate: true`, hollow pin, popup "approximate — district centre", still selectable), else not drawn (count shown: "N machines have no location").
- Colours: overdue red, due soon amber, when-in-area grey/muted, priority star marker; board To plan / Asked outlined, column named in popup. Engineer calls: blue squares.
- Ask engineer target = call picked in the side panel or clicked on the map; none picked → Ask disabled with "Pick a call first". Machines beyond `nearMiles` allowed, confirm text "N of these are over X miles from the call".
- Selection > 50 → confirmation in the app's Dialog (not `window.confirm`).
- Partial success reported: e.g. "3 asked Dave for Wed 25 Nov · 1 skipped: no longer due". To plan → Asked moves; already Asked gets the note line appended (existing `askNote`).
- Day switch Today / Tomorrow on the map, default Today. Calls without location listed "no location", not drawn.
- Map is a desktop tool but must not cause horizontal page scroll at phone width (16px gutter).
- Run `npm test`, `npm run typecheck`, `npm run lint` from repo root before each commit (lint's 3 known errors in `.superpowers/sdd/2026-11-18-pm-actions/*.ts` are pre-existing scratch files — ignore those only).

## Review Focus

1. A machine booked/dismissed/other-dealered by someone else between page load and the box action → skipped with a reason, others still done (Task 2 test `skips machines that left the map set`).
2. The chosen call vanished from the diary (refreshed away / engineer removed) → whole Ask refused with "That call is no longer in the diary — refresh the map" and nothing written (Task 2 test `refuses when the call is gone`).
3. Box drawn over empty map / only calls → selection stays empty, actions disabled (Task 3 test `box with no pins selects nothing`).
4. Many machines at one customer share identical coordinates → all selectable by box and listed individually in the selection panel (Task 3 test `stacked pins all inside box`).
5. Posted ids tampered/oversized (non-integers, > 500 ids, duplicates) → rejected before touching the DB (Task 3 test for `parseMapIds`).

  - `loadMapPins(db: Db, now?: Date, pmRows?: PmRow[]): Promise<{ pins: MapPin[]; unlocated: number }>` — candidates with `view === 'due' && dealer === null`; `at === null` counted in `unlocated`; Booked-column machines excluded (`boardColumn === 'booked'`); sorted priority, overdue months desc, id.

### Task 2: Batch plan from the map (DB)

**Files:**
- Modify: `packages/db/src/queries/pm-plan.ts` (or new `packages/db/src/queries/pm-map.ts` exported from `queries/index.ts` — builder's call)
- Test: matching `.test.ts`

**Interfaces:**
- Consumes: `loadMapPins` (Task 1), `addToPlan`, `moveCard`, `getScheduledCall` (existing), `askNote(engineerName, start)` — currently in `apps/web/src/lib/planner-upcoming.ts`; move it to `packages/db` (or `packages/core`) and re-export so web keeps working.
- Produces:
  - `export type MapSkipReason = 'not_on_map' | 'booked' | 'done'`
  - `export interface MapPlanResult { done: number[]; skipped: { vantageEquipmentId: number; reason: MapSkipReason }[]; call?: { engineerName: string; start: Date } }`
  - `planFromMap(db: Db, a: { vantageEquipmentIds: number[]; mode: 'add' | 'ask'; workUnitId?: number; userId: number; now?: Date }): Promise<MapPlanResult>`
    - Re-reads `loadMapPins` at call time; ids not in pins → `not_on_map`.
    - `add`: ids whose `boardColumn` is null → `addToPlan` (one call); already To plan / Asked count as done (no change).
    - `ask`: `getScheduledCall(workUnitId)`; null → throw `SettingsError('That call is no longer in the diary — refresh the map', 'call_gone')`, nothing written. Each id → `moveCard({ to: 'asked', appendNote: askNote(...) })`.

- [ ] **Step 1: Write failing tests:**
  - `adds unplanned machines to To plan` → `done` has both ids, `pm_plan.board_column = 'to_plan'`.
  - `asks engineer for many` → both in `asked`, note contains `Asked <engineer> for`, result `call.engineerName` set.
  - `skips machines that left the map set` → one dismissed machine → `skipped: [{ id, reason: 'not_on_map' }]`, other done.
  - `refuses when the call is gone` → unknown workUnitId → throws SettingsError, no `pm_plan` rows changed.
  - `already Asked gets the extra note line` → existing note kept, new line appended.
- [ ] **Step 2:** Run → FAIL. **Step 3:** Implement. **Step 4:** Run file + `npm test` → PASS.

### Task 3: Map helpers and server actions (web)

**Files:**
- Create: `apps/web/src/lib/planner-map.ts`, `apps/web/src/lib/planner-map.test.ts`
- Create: `apps/web/src/app/(app)/pm/planner/map-actions.ts`

**Interfaces:**
- Consumes: `MapPin`, `UpcomingCall`, `MapPlanResult`, `planFromMap`, `haversineMiles`.
- Produces (`planner-map.ts`, pure, no Leaflet import):
  - `export const OSM_TILES = 'https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png'`, `OSM_ATTRIBUTION = '© OpenStreetMap contributors'`
  - `export const MAP_CONFIRM_OVER = 50`, `MAP_IDS_MAX = 500`
  - `export type PinTone = 'overdue' | 'due_soon' | 'when_in_area' | 'other'` and `pinTone(p: MapPin): PinTone` (when-in-area wins over status).
  - `export interface Box { south: number; west: number; north: number; east: number }` and `selectInBox(pins: MapPin[], box: Box): number[]` (inclusive edges, input order).
  - `farFromCall(pins: MapPin[], call: { at: LatLng | null }, miles: number): number` — count of pins over `miles` (0 when call has no `at`).
  - `parseMapIds(raw: unknown): number[]` — array of positive safe integers, de-duplicated, 1..`MAP_IDS_MAX`, else throws `Error('bad ids')`.
  - `mapResultText(r: MapPlanResult, mode: 'add' | 'ask'): string` — e.g. `"4 added to plan"`, `"3 asked Dave for Wed 25 Nov · 1 skipped: no longer due"`. Reason copy: `not_on_map` → "no longer due", `booked` → "already booked", `done` → "already done".
- Produces (`map-actions.ts`, `'use server'`):
  - `mapAddToPlanAction(ids: number[]): Promise<{ ok: true; text: string } | { ok: false; error: string }>`
  - `mapAskEngineerAction(ids: number[], workUnitId: number): Promise<same>`
  - Both: `requireUser()` first, `parseMapIds`, `planFromMap`, `revalidatePath('/pm/planner')` + `('/pm')`, SettingsError → `{ ok: false, error: err.message }`, other errors logged → `"Couldn't save — try again"`. No redirect.

- [ ] **Step 1: Write failing tests** in `planner-map.test.ts`: `pinTone` (4 cases), `box with no pins selects nothing`, `stacked pins all inside box` (3 pins same coords → 3 ids), `edges are inclusive`, `farFromCall` (one at 5 mi, one at 20 mi, miles 10 → 1; call without `at` → 0), `parseMapIds` (rejects `'1'`, `[0]`, `[1.5]`, 501 ids, `null`; de-dups `[3,3,4]` → `[3,4]`), `mapResultText` (add, ask with skip).
- [ ] **Step 2:** `npx vitest run apps/web/src/lib/planner-map.test.ts` → FAIL. **Step 3:** Implement helpers + actions. **Step 4:** PASS; `npm run typecheck`.
- [ ] **Step 5:** Commit `feat(web): PM map helpers and actions`.

### Task 4: Map view UI

**Files:**
- Modify: `apps/web/package.json` (+ lock): `leaflet`, `react-leaflet`, `leaflet.markercluster`, `@types/leaflet`, `@types/leaflet.markercluster` — exact current versions, saved.

- Create: `apps/web/src/components/planner-map.tsx` (client shell: side panel, selection panel, buttons, dialogs, toasts), `apps/web/src/components/planner-map-canvas.tsx` (Leaflet only; loaded via `next/dynamic` with `ssr: false`), Leaflet CSS imported in the canvas file.

**Interfaces:**
- Consumes: `MapPin`, `UpcomingEngineer` (calls now with `at`), helpers + actions from Task 3, `nearMiles` from planner settings.
- Produces: `PlannerMap` props `{ pins: MapPin[]; unlocated: number; engineers: UpcomingEngineer[]; today: string; tomorrow: string; nearMiles: number }`.

Behaviour (spec + Global Constraints are binding):
- Canvas: OSM tiles; markercluster (default spiderfy at max zoom); pin markers via `L.divIcon` styled by `pinTone`, outline when `boardColumn` set, star when `priority`, hollow when `approximate`; call markers blue squares; ring `L.circle(nearMiles * 1609.344 m)` round the picked call. Fit bounds to pins on first load only (not after refresh).
- Box select: "Select area" toggle button + Shift-drag; while dragging map dragging is off, draw `L.rectangle`; on release `selectInBox` → add to selection. "Clear" empties.
- Side panel: Today / Tomorrow switch; engineers → calls (time, customer, "no location" when `at` null); click → pick call, pan to it, draw ring.
- Selection panel: count + list (customer, town, model, serial, due text) with untick per row; buttons **Add to plan** and **Ask <engineer> for <call>** (disabled "Pick a call first" when none). Over `MAP_CONFIRM_OVER` or any `farFromCall` > 0 → Dialog confirm with the counts. Result → sonner toast with `mapResultText`, selection clears, `router.refresh()`.
- Popup per pin: customer, town, model, serial, due text, column if on board, "approximate — district centre" when approximate, links to device page (`deviceHref` with back `/pm/planner?view=map`) and customer page.
- Footer note: "N machines have no location" when `unlocated > 0`.
